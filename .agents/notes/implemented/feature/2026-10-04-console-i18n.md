# Agent Note: 控制台中英国际化(cookie locale + 编译期键校验词典)

Status: implemented — 2026-10-04 首批迁移(壳层/登录/概览)落地,词典由 tests/i18n.test.ts 与 tsc 双重钉死;其余页面按触碰规则迁移

## Problem

控制台 UI 只有英文,中文用户需要国际化支持。全仓约 420 条展示字符串、53 个 tsx 文件,一次性全量迁移的 diff 风险与评审成本都不可接受;同时需要为"以后加语言/加页面"立一个不会漂移的机制。

## Decision

1. **零新依赖的手写方案,不引 next-intl**:仓库运行时依赖只有 5 个,需求(cookie 读取 + 词典查键)用 `next/headers` + 一个类型化对象即可满足;引入 i18n 框架换来的路由前缀、命名空间等能力当前用不上(独立开发者画像的否决票)。
2. **cookie locale,不做路由前缀**(`/en/…` `/zh/…`):所有页面本就是读 session/应用 cookie 的 server component,locale cookie 保持 URL 稳定、避免重构 28 个路由段;默认英文,未知值一律回退英文(fail-safe,不报错)。cookie 名 `monetplane_locale`,由 Topbar 的 LocaleSwitcher(Server Action 表单,无 JS 也可用)切换并 `revalidatePath("/", "layout")`。
3. **英文词典为类型真源**:`en` 是普通(非 as const)嵌套字符串对象;`type Dictionary = typeof en`;`const zh: Dictionary = {...}` ——任何语言缺键/多键都是**编译错误**,而非运行时空白。运行时再用 tests/i18n.test.ts 做键树奇偶 + 非空校验,防 `as` 逃逸。
4. **插值用 `{placeholder}` 令牌** + `formatMessage`(src/i18n/server.ts),唯一插值机制;含链接的句子拆成 before/link-label/after 三段模板,不做 JSX 注入字符串的黑魔法。
5. **客户端组件经 props 接收词典切片**(如 `labels: Dictionary["nav"]`),不做 client 侧词典上下文——server component 取词典后下传,保持 RSC 数据流。
6. **迁移范围(首批)**:根布局 `<html lang>`、侧边栏导航全量、Topbar、环境/项目切换器、登录页、概览页。**其余页面按童子军军规触碰时迁移**——每个页面迁移 = 把硬编码字符串搬进 en/zh 词典并在页面顶部 `const t = dictionary.<page>`,无需再动基建。

## Alternatives considered

- **next-intl / react-intl**:否决——零依赖手写满足全部需求;框架的路由前缀与 ICU 消息格式是当前规模下的过度工程,且增加一个需要跟随 Next 大版本升级的依赖。
- **路由前缀式 locale**:否决——28 个路由段重构 + URL 变化,对 cookie 驱动的控制台无收益。
- **`as const` 词典 + 字面量键**:否决——会把译文锁死成英文面值的字面量类型;普通对象 + typeof 恰好只校验键结构。
- **一次性全量迁移 53 文件**:否决——审查粒度差、回归面大;首批覆盖用户每天看到的壳层与首屏,余量走触碰规则。

## Consequences

- 未迁移页面暂保持英文(混合语言过渡态);每个页面迁移是纯机械 PR,基建不再变化。
- 新增语言 = 新增一个 `Dictionary` 类型文件 + LOCALES 联合扩展 + 切换器选项,编译器强制补全。
- 词典只放 UI 词汇;业务数据(商品名、客户邮箱等)与 StatusBadge 的状态枚举展示不翻译(状态是机器词汇,翻译会破坏与文档/API 术语的对应)。
- portal(面向终端客户)与 invitations 页未在首批;portal 需要单独一轮评估(其文案含品牌动态内容)。
